# Android 本地日志导入

从 0.14.1 开始支持本地日志解析；0.14.4 增加日志文件夹授权和自动读取。“我的 → 从日志导入 Key”及首页连接教程均可进入，原来的小米账号同步继续保留。0.14.10 增加自动识别设备、按设备分组和直接导入。

## 操作

1. 在小米运动健康中连接目标手环并同步一次。
2. 进入“我的 → 关于”，连续点击运动健康 Logo，按提示导出日志。不同版本入口或输出内容可能不同。
3. 首次授权 Download/wearablelog 或 Download/ResearchLog 子文件夹（Android 11 起不能授权整个 Download）。之后点击自动读取即可查找最新日志；从本页打开运动健康、导出并返回时会自动查找本次新日志。已具备所有文件访问权限时可直接查找这两个默认目录。本功能不主动索取该广泛权限。手动选择 ZIP/LOG/TXT 作为备用。
4. 在自动识别的设备列表中点击“选择并导入”，已有设备会按蓝牙地址更新 Key；有多个历史 Key 时先选择一条。只有无法识别的记录需要手动指定目标。
5. 保存后点击“验证连接”。日志可能包含历史 Key，能解析不代表连接认证一定成功。

不支持导出 Key 的版本仍可使用小米账号同步。请勿公开分享含连接凭据的日志。

## 数据与安全边界

- 单文件为临时权限；日志子文件夹采用可持久读取授权，可在页面取消。只在主动读取、授权成功或从本页打开运动健康返回时扫描，不后台轮询。仅保存文件夹 URI，不保存日志内容。
- 自动扫描最多 2048 个目录项、三层子目录；只选择 ZIP 或 XiaomiFit.main/device.log 及数字轮转后缀，跳过空文件与符号链接。返回运动健康时以打开时间过滤，避免把旧日志当成刚导出的日志。
- Android 工作线程流式读取 ZIP/文本，Dart isolate 本地解析候选记录，无服务器接口和日志上传。
- 不解压到磁盘、不创建日志缓存，不保存候选列表；原始日志由用户自行管理。
- 选中文件最多 32 MiB，ZIP 最多 256 个条目，单条目解压上限 64 MiB，总解压上限 128 MiB；候选 512 段/2 Mi 字符、最终最多 200 条 Key，并有超时限制。
- 长行仍按最多 128 Ki 字符窗口扫描并重叠 1024 字符。从 0.14.10 起，额外使用流式结构扫描器跟踪引号、转义和嵌套，提取跨窗口/跨行的完整设备对象；超大外层数组不妨碍提取内部的小型设备对象。每个结构帧最多 128 Ki 字符、结构栈最多 32 层，候选总预算和超时仍保留。0.14.11 改为检查 JSON 语法状态，普通日志标签不再累计为嵌套。超深子树只跳过结构识别，不中断整个读取；后续完整设备记录继续解析。截断或异常片段只提供待确认 Key，原生端通过 metadataAllowed 标记限制这类文本，避免在 Dart 端再次将其误判为可信设备资料。
- ZIP 中仅解析 XiaomiFit.main.log、XiaomiFit.device.log 及数字轮转后缀。跳过的条目也计入解压预算；异常路径拒绝处理。
- 同一完整 JSON 对象、已知 deviceInfo/device/detail/product 结构可提供设备资料；分散记录只通过明确的 did、deviceId 或序列号关联到唯一完整蓝牙地址。标识对应多个地址时不自动关联，不用名称或邻近日志顺序猜测。重复 Key 去重，同一设备不同历史 Key 保留供选择。
- 自动识别到地址时，点击“选择并导入”即可新增设备或按地址更新已有设备的 Key，保留已有自定义名称等资料；只有无法可靠识别的记录才显示手动目标表单。历史 Key 不按出现顺序自动认定最新，导入后需验证连接。
- UI 隐去大部分 Key。用户确认后通过现有设备导入队列写入安全存储，只更新确认的设备；连接认证失败会明确提示，新 Key 不会自动回滚。
- 本次不更改服务端或 Windows 客户端。隐私政策版本更新以披露本地日志处理。

## 验证

原生 Java 测试覆盖 UTF-8、多条目、损坏/异常路径/过多条目、过长行、候选限制及无关条目的压缩膨胀。Dart 测试覆盖多设备元数据隔离、历史 Key、旧文本格式、掩码与输入限制；组件测试覆盖明确选择目标、地址不匹配拦截和取消选择。真机的运动健康导出入口、系统文件提供器和蓝牙认证仍需设备验证。
